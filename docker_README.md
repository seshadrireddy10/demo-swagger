# Docker A to Z Command Reference

This document serves as a comprehensive reference guide for Docker commands, organized by their core operational purpose.

---

## 📈 1. Container Lifecycle Management

These commands handle the creation, execution, and destruction of containers.

```
[ Image ] ── (run / create) ──> [ Container (Stopped) ] ── (start) ──> [ Container (Running) ]
                                      ▲                                       │
                                      └───────────── (stop) ──────────────────┘
```

*   **`docker run`**: Creates and starts a container from an image.
    ```bash
    docker run -d -p 8080:80 --name my-web nginx
    ```
    *   `-d`: Runs container in detached mode (background).
    *   `-p`: Maps host port 8080 to container port 80.
*   **`docker create`**: Creates a new container but does not start it immediately.
    ```bash
    docker create --name static-container ubuntu
    ```
*   **`docker start`**: Starts one or more stopped containers.
    ```bash
    docker start my-web
    ```
*   **`docker stop`**: Gracefully stops a running container by sending a `SIGTERM` signal.
    ```bash
    docker stop my-web
    ```
*   **`docker restart`**: Restarts a container (stops and then starts it again).
    ```bash
    docker restart my-web
    ```
*   **`docker pause`**: Suspends all processes within a running container using the `cgroups` freezer.
    ```bash
    docker pause my-web
    ```
*   **`docker unpause`**: Resumes all processes within a paused container.
    ```bash
    docker unpause my-web
    ```
*   **`docker kill`**: Forcefully terminates a container by sending a `SIGKILL` signal.
    ```bash
    docker kill my-web
    ```
*   **`docker rm`**: Deletes one or more stopped containers from disk.
    ```bash
    docker rm my-web
    ```
    *   *Note:* Use `docker rm -f` to force-remove a running container.

## 🔎 2. Inspection and Observability

Use these commands to debug, view performance metrics, and audit your running systems.

*   **`docker ps`**: Lists running containers.
    ```bash
    docker ps -a
    ```
    *   `-a`: Shows all containers (both running and stopped).
*   **`docker logs`**: Retrieves log output generated by a container.
    ```bash
    docker logs -f --tail 50 my-web
    ```
    *   `-f`: Follows/streams the log output in real time.
    *   `--tail 50`: Shows only the last 50 lines.
*   **`docker inspect`**: Returns low-level, detailed JSON configuration data for a container or image.
    ```bash
    docker inspect my-web
    ```
*   **`docker stats`**: Displays a live, streaming format of container resource usage statistics (CPU, memory, network I/O).
    ```bash
    docker stats
    ```
*   **`docker top`**: Displays the active running processes inside a specific container.
    ```bash
    docker top my-web
    ```
*   **`docker port`**: Lists the network port mappings or a specific mapping for the container.
    ```bash
    docker port my-web
    ```
*   **`docker diff`**: Inspects changes to files or directories on the container's filesystem since it was created.
    ```bash
    docker diff my-web
    ```

## 🛠 3. Interaction and Execution

These tools allow you to step inside a container or move files between the host and container layers.

*   **`docker exec`**: Runs a new command inside an already running container.
    ```bash
    docker exec -it my-web /bin/bash
    ```
    *   `-i`: Keeps STDIN open (interactive).
    *   `-t`: Allocates a pseudo-TTY (terminal interface).
*   **`docker attach`**: Attaches your local terminal to the primary running process (PID 1) inside a container.
    ```bash
    docker attach my-web
    ```
*   **`docker cp`**: Copies files or folders between a container and the local filesystem.
    ```bash
    # Copy from host to container
    docker cp index.html my-web:/usr/share/nginx/html/

    # Copy from container to host
    docker cp my-web:/var/log/nginx/error.log ./error.log
    ```

## 📦 4. Image Management

Commands dedicated to downloading, building, modifying, and publishing Docker images.

*   **`docker build`**: Builds a Docker image from a local `Dockerfile`.
    ```bash
    docker build -t my-app:v1 .
    ```
    *   `-t`: Applies a name/tag format (`name:tag`).
    *   `.`: Points to the build context directory.
*   **`docker images`**: Lists all locally stored Docker images.
    ```bash
    docker images
    ```
*   **`docker pull`**: Downloads an image or a repository from a registry (like Docker Hub).
    ```bash
    docker pull alpine:latest
    ```
*   **`docker push`**: Uploads a locally tagged image to a remote registry.
    ```bash
    docker push username/my-app:v1
    ```
*   **`docker tag`**: Creates a pointer reference alias targeting an existing image.
    ```bash
    docker tag my-app:v1 username/my-app:v1
    ```
*   **`docker rmi`**: Deletes one or more local images.
    ```bash
    docker rmi alpine:latest
    ```
*   **`docker commit`**: Creates a new image from a container's current configuration changes (useful for quick debugging snapshots).
    ```bash
    docker commit my-web my-debug-image:v1
    ```
*   **`docker save`**: Saves one or more images to a tar archive file (useful for offline transfers).
    ```bash
    docker save -o my-image.tar my-app:v1
    ```
*   **`docker load`**: Loads an image from a tar archive standard input or file.
    ```bash
    docker load -i my-image.tar
    ```
*   **`docker history`**: Shows the history/layers of an image.
    ```bash
    docker history my-app:v1
    ```

## 💾 5. Volume and Data Persistence

Volumes decouple the lifecycle of application data from the lifecycle of the container.

```
[ Host Storage: /var/lib/docker/volumes/ ]  <==== Mounts To ====>  [ Inside Container: /data ]
```

*   **`docker volume create`**: Creates a named, managed storage volume.
    ```bash
    docker volume create db_data
    ```
*   **`docker volume ls`**: Lists all local volumes managed by Docker.
    ```bash
    docker volume ls
    ```
*   **`docker volume inspect`**: Displays detailed configuration data about a volume.
    ```bash
    docker volume inspect db_data
    ```
*   **`docker volume rm`**: Removes a specific volume (the volume must not be in use by any container).
    ```bash
    docker volume rm db_data
    ```
*   **`docker volume prune`**: Deletes all unused local volumes to free up disk space.
    ```bash
    docker volume prune
    ```

## 🌐 6. Network Management

Manage how containers communicate with each other, the host, or external networks.

*   **`docker network create`**: Creates a new isolated network (usually using the bridge driver).
    ```bash
    docker network create app-net
    ```
*   **`docker network ls`**: Lists all networks configured on the Docker host.
    ```bash
    docker network ls
    ```
*   **`docker network connect`**: Connects a running container to an existing network.
    ```bash
    docker network connect app-net my-web
    ```
*   **`docker network disconnect`**: Disconnects a container from a network.
    ```bash
    docker network disconnect app-net my-web
    ```
*   **`docker network inspect`**: Displays detailed information about a network, including connected container IP addresses.
    ```bash
    docker network inspect app-net
    ```
*   **`docker network rm`**: Removes one or more networks.
    ```bash
    docker network rm app-net
    ```

## 🧼 7. System Cleaning and Maintenance

Commands designed to clear cache and reclaim system space.

*   **`docker system df`**: Displays total disk usage breakdown by containers, images, volumes, and build cache.
    ```bash
    docker system df
    ```
*   **`docker system prune`**: Cleans up your system by removing stopped containers, unused networks, and dangling images.
    ```bash
    docker system prune -a --volumes
    ```
    *   `-a`: Removes all unused images, not just dangling ones.
    *   `--volumes`: Includes unused volumes in the wipe out.
